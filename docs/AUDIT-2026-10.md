# Technical audit, October 2026

**Date:** 16 October 2026 · **Branch:** `audit/full-audit` (not pushed, not merged) ·
**Scope:** backend (Django, `backend/apps/*`), frontend (Next.js, `frontend/src`), CI and
deployment files. Follows the September audit in `AUDIT.md`, focusing on what changed since:
SENDI, manual top-ups, rentals and extensions, referrals, funding, number-issue reports and
the admin reporting added in October.

Everything here was run locally against mocks and SQLite. No production data, payments,
refunds or provider credit were touched.

## A. Summary

The money core is in good shape. The ledger (`wallet/services.py`) is the only balance
writer, with row locks, compare-and-set, unique idempotency keys and database CHECKs. Webhooks
verify signatures on raw bytes, are replay-safe, and SENDI and Moolre treat a webhook only as a
prompt to ask the provider's verify endpoint. Order and rental purchases charge inside one
transaction and call the provider outside it, with automatic refunds keyed for idempotency.
Customer endpoints filter by owner. No secret was found in git history.

The problems found are in **reporting, role boundaries and dependencies**, not in balances:

1. **Revenue overstated** after refunds on delivered orders, on the dashboard, charts and
   Funding page. Fixed.
2. **Refunded tile undercounted**: rental and extension refunds were missing. Fixed.
3. **SUPPORT could read provider cost, FX and profit**, which the role matrix gives only to
   PRICING_VIEW (admins). Fixed.
4. **Login CSRF**: sign-in accepted cross-site form posts. Fixed.
5. **Outdated, vulnerable dependencies**: Django 5.0.9 is end-of-life with 23 advisories.
   Bumped on the branch to a patched set that passes the full suite. Next.js 14.2.35 has
   critical advisories, including one for apps using CSP nonces, which this app does; that
   needs a major upgrade and is left as a plan.
6. **CI was red on `main`**: 48 ruff errors stopped the backend job before its tests, and
   an out-of-sync `package-lock.json` stopped the frontend job at `npm ci`. Both fixed; the
   PR's CI is green on PostgreSQL 16.

### Checked and holding

- **Ledger:** single writer, locks plus compare-and-set, unique `(wallet, idempotency_key)`,
  contiguous sequence, nightly integrity check. Rental charges and refunds use the same keys
  pattern as orders.
- **Webhooks:** constant-time HMAC on raw bytes (SENDI SHA-512), provider-mismatch guard,
  replay index, failed events re-applied by sweep, unparseable events kept for humans.
  SENDI credits only on its verify answer with matching reference, currency, amount and
  live mode.
- **Deposits never count as revenue:** revenue reads orders, rentals and extensions only;
  deposits appear separately as `payments`/`deposits`.
- **Manual top-ups:** credited only by staff with WALLET_ADJUST, receipt ID unique by DB
  constraint, ledger key per payment.
- **Ownership:** every customer viewset filters by `request.user`.
- **Historical prices:** price, provider cost and FX are frozen on each order, rental and
  extension; reports use the frozen rate.
- **Secrets:** no real key in git history (only placeholders in docs and a test literal);
  production refuses test keys, mock providers and a missing JWT key.
- **Background jobs:** every sweep that settles money (payments, webhooks, orders, rentals,
  extensions) is on the beat schedule.

## E. Release readiness

**Verdict: ready to merge the branch; not ready to call production fully hardened.**

The fixes are small, tested and confined to reporting, role visibility and sign-in parsing.
No balance-moving code changed. Before treating the platform as hardened: deploy the
Django and auth-stack upgrade through staging (A-06), schedule the Next.js upgrade (A-07),
and look over the admin dashboard once as a SUPPORT user. The PR's CI is green on
PostgreSQL 16, which also closes the September audit's open item O-1.
